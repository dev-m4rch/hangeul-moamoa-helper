# 한글 모아모아 배치 도우미

메이플스토리 미니게임 **한글 모아모아**에서, 현재 판과 받은 조각 3개를 넣으면 어디에 어떤 순서로 놓을지 찾아 주는 웹 도구입니다. 게임 화면을 읽거나 게임에 입력하지 않고, 사용자가 판을 직접 옮겨 적는 방식입니다.

## 실행 방법

설치할 것은 없습니다. `index.html` 파일 하나로 동작합니다.

- **내려받아 열기**: 이 저장소에서 `index.html`을 내려받아(또는 `Code → Download ZIP`) 브라우저로 엽니다.
- **GitHub Pages로 열기**: 저장소 `Settings → Pages`에서 Source를 `Deploy from a branch`, Branch를 `main` / `(root)`로 저장하면 `https://dev-m4rch.github.io/hangeul-moamoa-helper/` 주소로 열립니다.

## 플레이 방법

1. **판 맞추기**: 게임을 새로 시작했다면 그대로 두고, 진행 중이라면 "블록 칠하기"로 게임판과 똑같이 칸을 누르거나 끌어서 칠합니다.
2. **조각 고르기**: 게임에서 받은 조각 3개를 "조각 고르기"에서 누릅니다. 방향은 맞출 필요 없습니다. 잘못 담았으면 "보유 조각"의 조각을 눌러 뺍니다.
3. **자동 배치**: "자동 배치" 버튼이나 `Enter`를 누릅니다. 계산은 1~3초쯤 걸립니다.
4. **게임에 옮기기**: "놓는 순서"에 나온 1 → 2 → 3 순서대로, 그림과 같은 모양이 되게 회전·반전해서 표시된 자리에 놓습니다. 순서를 바꾸면 줄이 지워지는 시점이 달라져 결과가 달라질 수 있습니다.
5. **반복**: 판은 자동으로 다음 상태가 됩니다. 새로 받은 조각 3개를 다시 고르고 자동 배치를 누릅니다.

### 화면 인식 (실험 기능)

매번 조각을 누르는 대신, 게임 화면을 공유해 보유 조각 3개를 자동으로 담을 수 있습니다.

1. "화면 인식 시작"을 누르고, 브라우저의 공유 창에서 메이플스토리 창(또는 그 화면 전체)을 고릅니다.
2. 한글 모아모아 창의 "보유 조각" 3칸이 화면에 보이면 조각이 자동으로 담깁니다.
3. 세 조각을 모두 사용해 새 조각 3개가 나오면 자동으로 다시 인식하고 배치까지 계산합니다. 계산은 직접 누르고 싶으면 "인식되면 바로 자동 배치"를 끕니다.

- 화면은 브라우저 안에서만 읽고 어디로도 보내지 않습니다. 게임에 입력하지도 않습니다.
- PC의 Chrome · Edge 같은 브라우저에서 동작합니다. 메이플스토리는 창 모드여야 화면 공유에 잡힙니다.
- 인식하는 것은 **보유 조각뿐**입니다. 게임판과 능력 아이콘은 읽지 않으므로, 판은 지금처럼 도우미가 계산한 대로 따라 놓아야 맞습니다.
- 놓으려고 조각을 선택해 카드가 노랗게 바뀐 상태, "사용 완료"로 바뀐 카드도 구분해서 읽습니다.
- 바꿔 뽑기로 조각이 바뀌면 바뀐 3개가 다시 담깁니다. 그 턴에 이미 놓은 조각이 있으면 손으로 빼 주세요.
- 실제 게임 화면 캡처 1장과 합성 그림으로만 검증했습니다. 해상도나 화면 효과에 따라 못 읽는 경우가 있을 수 있습니다.

### 판에 표시되는 것

| 표시 | 뜻 |
| --- | --- |
| 흰 칸 | 이미 놓여 있는 블록 |
| 숫자가 있는 색 칸 | 이번 턴에 놓은 조각 (숫자 = 놓는 순서) |
| 점선 칸 | 이번 턴에 꽉 차서 사라진 줄. 숫자가 있으면 이번에 놓은 조각, 없으면 원래 있던 블록 |
| ◎ | 능력 아이콘 |

점선 칸과 순서 번호는 다음 자동 배치 때 지워지고 새로 표시됩니다.

### 능력과 그 밖의 조작

- **능력 아이콘**: 게임판에 아이콘이 생기면 "◎ 능력 아이콘" 도구로 같은 칸을 눌러 표시합니다(최대 3개). 그 줄을 지우는 수를 더 높게 평가합니다.
- **점 찍기**: "점 찍기 1개 함께 쓰기"를 체크하고 자동 배치하면 점 찍기 위치까지 포함해 알려 줍니다.
- **바꿔 뽑기**: 조각을 놓을 자리가 없으면 안내 문구가 나옵니다. 게임에서 바꿔 뽑은 뒤 새 조각을 골라 다시 자동 배치합니다.
- **조각 우클릭**: 그 조각 하나만 바로 배치합니다.
- **놓는 순서 기록**: 최근 5턴까지 남고, 가장 최근 턴이 맨 위에 나옵니다.
- **되돌리기**: "되돌리기" 버튼 또는 `Ctrl`+`Z`.
- **판 비우기**: 새 게임을 시작할 때 누릅니다. 판, 보유 조각, 점수가 모두 초기화됩니다.

진행 상태는 브라우저에 저장되어 새로고침해도 남습니다.

## 반영한 게임 규칙

- 판은 가로 10칸 × 세로 16칸, 조각은 19종이며 회전·반전할 수 있습니다.
- 가로줄이 꽉 차면 지워지고, 나머지 줄은 내려오지 않습니다.
- 점수는 조각 칸 수 + 동시에 지운 줄 수 n에 대해 300 × n² 입니다(1줄 300 · 2줄 1,200 · 3줄 2,700 · 4줄 4,800 · 5줄 7,500).
- 능력 아이콘이 있는 줄을 지우면 능력과 50점을 얻습니다.

## 알고리즘

한 줄로 요약하면 **빔 탐색(beam search)으로 후보 배치를 만들고, 휴리스틱 평가 함수로 추린 뒤, 무작위 다음 손패를 시뮬레이션(몬테카를로 미리보기)해서 최종 선택**합니다. 학습된 모델은 쓰지 않으며 전부 `engine.js` 안의 순수 계산입니다.

### 1. 판과 조각 표현

- 판은 줄마다 10비트 정수 하나, 총 16개 정수로 표현합니다(비트보드). 조각이 들어가는지는 `판의 줄 & (조각 줄 << 열)`이 0인지로, 줄 완성은 값이 `1023`(10비트 모두 1)인지로 판정합니다.
- 조각 19종은 미리 회전 4방향 × 반전 2가지를 만들어 중복을 제거해 둡니다. 조각에 따라 서로 다른 방향은 1~8개입니다.

### 2. 빔 탐색: 이번 턴의 배치 후보 만들기

조각 3개를 놓는 방법은 `순서 × 방향 × 위치`의 조합이라 전부 따지면 수억 가지가 됩니다. 그래서 단계마다 좋은 것만 남기는 빔 탐색을 씁니다.

1. 조각 3개의 놓는 순서(최대 6가지, 같은 조각이 있으면 중복 제거)를 하나씩 시도합니다.
2. 첫 조각을 놓을 수 있는 모든 방향·위치에 놓아 보고, 줄이 꽉 차면 즉시 지웁니다.
3. 결과 판이 같은 것은 하나로 합치고(점수가 높은 쪽 유지), `지금까지 얻은 점수 + 판 평가값`이 높은 순으로 **상위 30개**만 남깁니다.
4. 남은 판 각각에 다음 조각을 같은 방식으로 놓습니다. 세 번째 조각까지 반복합니다.

줄 삭제는 조각을 놓는 즉시 일어나므로, 앞 조각이 줄을 지워야 뒤 조각이 들어갈 수 있는 수순도 자연스럽게 찾아집니다. 세 조각을 다 놓는 방법이 없으면 가장 많이 놓는 수순을 돌려줍니다.

### 3. 판 평가 함수

이 게임은 줄이 지워져도 위 블록이 내려오지 않습니다. 그래서 테트리스식 "높이"는 의미가 없고, **적은 줄에 몰아 채우고 넓은 빈 공간을 남긴 판**을 좋은 판으로 봅니다. 평가값은 아래 항목의 가중합입니다.

| 항목 | 의미 | 가중치 |
| --- | --- | --- |
| 손댄 줄 | 블록이 하나라도 있는 줄마다 벌점. 빈 칸이 많을수록 더 큼 → 여러 줄에 흩뿌리지 않고 한 줄씩 끝내게 함 | 줄당 −20, 빈 칸당 −6 |
| 가로 경계 | 한 줄 안에서 채움/빈 칸이 바뀌는 횟수(벽은 채워진 것으로 봄). 들쭉날쭉한 줄일수록 완성하기 어려움 | 경계당 −12 |
| 세로 경계 | 위아래 줄 사이에서 채움/빈 칸이 다른 칸 수 | 칸당 −6 |
| 고립된 한 칸 | 상하좌우가 모두 막힌 빈 칸. 점 찍기나 1칸 조각 없이는 메우기 어려움 | 칸당 −60 |
| 3×3 빈 공간 | 3×3 빈 정사각형이 들어가는 자리 수(최대 30). ㅁ ㅂ ㅒ ㅎ 같은 큰 조각을 받을 여유 | 자리당 +4 |
| 조각별 놓을 자리 | 19종 각각 놓을 수 있는 자리가 4곳 미만이면 벌점, 한 곳도 없으면 2배 | 조각당 최대 −(400 + 5×칸 수)×2 |

앞의 다섯 항목은 비트 연산만으로 계산되어 탐색 중 모든 판에 적용합니다. 마지막 "조각별 놓을 자리"는 비용이 커서 세 조각을 다 놓은 최종 판 상위 12개에만 적용합니다.

능력 아이콘(◎)이 있는 줄을 지우는 수는 250점짜리로 계산합니다(게임 점수 50점 + 능력 자체의 가치).

### 4. 미리보기: 다음 손패 시뮬레이션

평가 함수만으로는 "지금은 좋아 보이지만 다음 턴에 막히는 판"을 걸러내기 어렵습니다. 그래서 최종 후보를 한 번 더 검증합니다.

1. 순서를 통틀어 가장 좋은 최종 판 **상위 8개**를 고릅니다.
2. 무작위 다음 손패(조각 3개) **24세트**를 뽑습니다. 모든 후보에 같은 24세트를 써서 운에 따른 차이를 없앱니다.
3. 후보 판마다 24세트를 각각 작은 빔 탐색(폭 4)으로 실제로 풀어 봅니다. 조각을 못 놓으면 조각당 −3,000의 벌점을 줍니다.
4. `이번 턴 점수 + 24세트 결과의 평균`이 가장 높은 후보를 최종 답으로 냅니다.

즉 한 번의 자동 배치는 "이번 턴 탐색 1회 + 다음 턴 탐색 192회(8 × 24)"로 이루어집니다.

### 5. 가중치를 정한 방법

`sim.js`로 무작위 조각을 주며 능력 없이 끝까지 두는 자가 대국을 돌려, 평균 생존 턴이 더 긴 쪽으로 가중치를 손으로 조정했습니다. 미리보기를 켜면 같은 조건에서 생존 턴이 눈에 띄게 늘었습니다(6판 평균 51턴 → 샘플 12세트에서 89턴). 판 수가 적어 오차가 큰 수치입니다.

### 한계

- 다음 조각은 19종이 같은 확률로 나온다고 가정합니다. 실제 확률은 공개되지 않았습니다.
- 능력을 전혀 쓰지 않는 자가 대국에서는 평균 60~70턴, 4만 점대에서 막혔습니다. 항상 최선의 수를 보장하지는 않습니다.
- 바꿔 뽑기를 언제 쓰면 이득인지는 계산하지 않습니다.
- "다음 능력 획득까지" 횟수와 능력 보유 개수는 추적하지 않습니다.

## 파일 구성

| 파일 | 내용 |
| --- | --- |
| `index.html` | 실행 파일. `build.py`가 만든 결과물 |
| `page.src.html` | 화면(HTML · CSS · UI 스크립트) 원본 |
| `engine.js` | 조각 정의, 규칙, 평가 함수, 탐색 |
| `build.py` | `page.src.html`에 `engine.js`, `vision.js`를 끼워 `index.html` 생성 |
| `vision.js` | 화면 인식: 보유 조각 카드 찾기, 조각 모양 읽기 |
| `test/vision_test.js` | 화면 인식 검사 (`node test/vision_test.js`) |
| `sim.js` | 규칙 검사 + 자가 대국 (`node sim.js [판수] [최대턴] [가중치JSON] [빔] [샘플] [후보수]`) |
| `fuzz.js` | 배치 결과가 기존 블록을 잃지 않는지 무작위 검사 (`node fuzz.js`) |

화면이나 엔진을 고친 뒤에는 `python3 build.py`로 `index.html`을 다시 만듭니다.
